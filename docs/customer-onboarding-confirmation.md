## 3. 对接前置准备（客户侧操作）

- [ ] 开通测试环境账号（由我方提供租户 ID 与管理员账号）
- [ ] 获取 JWT Token：调用 `POST /api/auth/login` 获取 `data.token`
- [ ] 多租户请求头：业务接口建议携带 `X-Tenant-Id: <租户ID>`
- [ ] 鉴权方式：除登录与渠道 Webhook 外，所有接口请求头携带 `Authorization: Bearer <token>`

## 4. 核心对接接口（基础对接范围）

| 模块 | 接口 | 说明 |
| --- | --- | --- |
| 认证 | `POST /api/auth/login` | 获取 JWT，建议按文档中"登录"分组 |
| 渠道事件接入 | `POST /api/channel/events` | 三渠道 Webhook 统一入口，幂等去重；无鉴权（渠道平台回调） |
| 线索 | `/api/leads/**` | 线索新增/查询/状态流转 |
| 客户 | `/api/customers/**` | 客户档案与跟进记录 |
| 会话 | `/api/conversations/**`、`/api/messages/**` | 会话与消息 CRUD |
| AI 回复 | `/api/chat/**` | AI 智能回复（可配置自动转人工） |
| 数据统计 | `/api/dashboard/**` | 基础数据看板 |

> 全部接口明细以 `openapi.json` / 离线文档为准，本章节仅列基础对接优先级。

## 5. 客户侧对接确认项（由客户侧技术勾选）

对接完成后，客户侧技术逐一确认：

- [ ] 已成功导入 `openapi.json` 到 Apifox/Postman，接口路径、请求方式、参数与文档一致
- [ ] `POST /api/auth/login` 可正常获取 Token，携带 Token 可访问受保护接口
- [ ] 渠道事件接入：模拟回调可收到事件并返回 `true`（重复事件返回 `false`）
- [ ] 线索/客户/会话/消息基础 CRUD 调用通过，返回结构 `{ code, message, data }` 理解无误
- [ ] 错误码对照表可查：调用失败时能根据 `code` 独立判断原因（无需咨询我方）
- [ ] 分页结构 `PageResult{ page, size, total, pages, records }` 解析正确
- [ ] 实时消息推送（如使用）已按 `websocket-guide.md` 完成联调
