# 架构决策记录

## ADR-001 模块化单体

状态：已接受。采用 Java 17、Spring Boot 和 Maven 多模块的模块化单体。当前团队与业务规模下，单事务和统一部署降低一致性成本；领域边界通过应用接口、事件和 ArchUnit 固化，为未来按热点拆分保留条件。

## ADR-002 PostgreSQL 单数据库方言

状态：已接受。官方运行基线为 PostgreSQL 16+，Flyway 管理版本，不维护 MySQL 双方言。选择依据是部分唯一索引、`JSONB`、`TIMESTAMPTZ`、CTE 条件更新和后续 RLS 能力。数据库选型变化必须新建 ADR，并评估迁移脚本、锁语义、索引和测试矩阵，不得在业务 SQL 中临时兼容。

## ADR-003 事务 Outbox

状态：已接受。跨上下文传播使用业务事务内 Outbox，RabbitMQ 仅负责传输。该决策避免数据库提交与消息发送之间的不一致。

## ADR-004 新旧接口并行

状态：已接受。新接口统一使用 `/api/v1`；旧接口在迁移期保留，但覆盖到新领域能力后必须改为应用服务适配器，禁止新增直接 Mapper 访问或双写。删除旧实现需有契约测试和回滚方案。

## ADR-005 多租户共享表

状态：已接受。首期使用共享表、租户拦截/上下文、Repository 强制条件和隔离测试；PostgreSQL RLS 作为后续纵深防御，不替代应用层授权。
