# 交易域上下文登记

产品与价格目录已在阶段 2A 通过 V10 建表，商机管道已在阶段 2B 通过 V11 建表，报价根、版本和快照行已在阶段 2C 通过 V12 建表，审批定义及运行事实已在阶段 2D 通过 V13 建表。阶段 3 的合同、合同变更、销售订单和取消申请物理模型已在 V14 建表，来源唯一性约束在 V15/V16 固化，V17 补齐 CRM 内部生命周期、权限和关闭原因约束。CRM 的交易边界止于销售订单，不扩展交付、回款、开票或售后域。

| 上下文 | 对象 | 主键与租户 | 跨域引用规则 |
|---|---|---|---|
| Catalog | 分类、产品、价目表、价格项已实现；折扣规则待后续迁移 | Snowflake `BIGINT`；租户表必带 `tenant_id` | 销售/交易只存 `product_id/price_list_id` 和成交快照；不 FK 到 Catalog |
| Opportunity | 商机、阶段历史、输单、重启已实现 | 聚合根和历史均 Snowflake；租户隔离 | 引用 `customer_id/contact_id/source_lead_id`；客户主数据不反向持有商机字段 |
| Quotation | 报价、报价版本、报价行和报价审批已实现 | 报价根 ID + 版本 ID；租户隔离 | 引用商机/客户/价目表；每版固化产品、价格、税率和币种快照 |
| Contract | 合同草稿、签署撤回、签署、作废和合同变更审批台账已实现 | 合同根和变更 ID；租户隔离 | 引用获批报价/客户 ID；V15 保证一个报价版本仅有一个有效合同；已签合同和订单快照不被变更审批改写 |
| Order | 销售订单草稿、确认、取消申请及审批、关闭已实现 | 订单根和行 ID；租户隔离 | 引用合同、客户、产品 ID；订单行保留商业快照。订单关闭由 CRM 销售流程显式完成，不依赖外部履约结果 |

全局规则：金额 `NUMERIC(18,2)`，币种 ISO 4217，时间 UTC `TIMESTAMPTZ`；跨上下文只保存 ID，不建实体级 FK；跨域一致性依赖应用校验和 Outbox 事件。除已实现的目录、商机、报价、审批、合同和销售订单表外，禁止创建交付、收款、发票、工单等正式表，现有静态测试继续校验 `crm_delivery`、`crm_payment`、`crm_invoice` 和 `crm_ticket` 不存在。
