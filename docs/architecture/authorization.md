# 租户、组织、数据范围与字段权限

## 租户和组织

共享表多租户是当前唯一模式。认证结果提供可信 `tenant_id/user_id`，客户端租户头只能用于一致性校验，不能覆盖认证主体。所有 Repository 查询、更新和删除必须显式包含 `tenant_id`；ID 命中但租户不符时统一返回不存在。

用户必须属于同租户的一个启用部门。部门使用物化路径 `path` 表达树，例如 `/11/12`；移动部门是高风险批量操作，需校验无环、重写子树路径并审计。用户停用后不能作为新负责人，但历史中的用户 ID 保留。

## 数据范围

| 值 | 可见记录谓词 |
|---|---|
| `SELF` | `owner_user_id = actor.user_id` |
| `DEPARTMENT` | `owner_dept_id = actor.department_id` |
| `DEPARTMENT_AND_SUB` | `owner_dept_id IN (同租户且 path 位于 actor.path 子树的部门)` |
| `ALL` | 同租户全部记录 |

同一用户多角色取数据范围并集，但始终受租户边界限制。私海列表和详情使用同一谓词；公海读取还需资源权限，认领/分配用独立权限码。查询 SQL 先限定 `tenant_id`，再限定范围，且不得在内存中过滤越权数据。

## 字段权限与敏感数据

`crm_role_field_permission` 以角色、资源、字段配置 `can_view/can_edit/can_export`。多角色同字段取并集；没有配置时默认拒绝敏感字段，普通字段按功能权限开放。`can_edit` 和 `can_export` 必须以 `can_view=true` 为前提。

手机号、邮箱、身份证件、地址、聊天原文和财务信息属于敏感字段。列表默认脱敏；详情仅在 `can_view` 后解密；导出必须同时具备资源导出权限和字段 `can_export`，并记录导出条件、字段集合、行数和 trace。搜索可使用规范化哈希列（后续迁移增加），禁止用明文日志定位。

## 高风险操作

转换、合并、分配、批量、导出、离职交接、审批管理和 Outbox 人工重试必须使用独立权限码，不得由通用编辑权限隐式获得。服务端按“租户 -> 用户启用 -> 功能权限 -> 数据范围 -> 字段权限 -> 状态前置条件 -> 乐观锁”的顺序授权。
